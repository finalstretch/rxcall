# Decisions

One dated paragraph per product or architecture decision. Newest at the bottom.

---

**2026-09-11 — Rxcall scope: drug recalls only, via openFDA.** The broader idea was a unified recall matcher across openFDA (drugs), CPSC (consumer products), and USDA FSIS (meat/poultry). We're starting with drugs only. One data source is shippable by one developer in a few months; three means three ingestion layers and three matching problems before anything reaches a user. openFDA is also the best-behaved of the three: JSON, no API key, structured `classification`, `code_info` (lot numbers), and an `openfda` block with brand/generic names and NDC codes on many records. CPSC and FSIS can be added later behind the same "your list vs. the feed" model. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-09-11 — No openFDA API key.** openFDA works without a key at 240 requests/minute and 1,000/day per IP. That's more than one phone will ever use, and a key would be a secret in a repo that's going public. If we ever hit the limit, the fix is fewer/larger queries, not a key. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-09-11 — Matching is presented as "possible match," never "recalled," unless the NDC matches.** Many enforcement records lack the `openfda` block, so matching often falls back to text search over `product_description`. Text matches can be wrong in both directions. The UI says what kind of match it is and always shows the lot numbers so the user can compare with their bottle. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-09-11 — `main` review requirement is by agreement, not enforced, while the repo is private.** The project rule is that `main` takes one approving review and no direct pushes. GitHub only enforces branch protection on public repos or paid plans, and we're not paying for anything before there's an entity to pay. So for now: the repo stays private, nobody pushes to `main` (all changes are PRs, the other sibling reviews), and enforcement is turned on the day the repo goes public. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-09-19 — Drug names are matched on the device against a bundled list, not looked up by API.** Scanning a label reads the patient's name, prescriber, and pharmacy along with the drug. If the app sent label text to an API to work out which drug it was, that personal text would leave the phone. Instead `tools/build_drug_index.py` turns openFDA's NDC dataset into a ~0.5 MB list of brand/generic names shipped in the app, and `DrugIndex` matches OCR'd lines against it locally. Only the confirmed drug name is ever sent, to the FDA recall API, exactly as if it had been typed. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-09-19 — Recall alerts are local notifications from a background check; there is no push server.** The app registers a BGAppRefreshTask that re-runs the same direct api.fda.gov query the person could tap themselves, compares against the results cached on the medication, and posts a notification composed on the phone. No device token is registered anywhere and nothing new leaves the device. The cost is that iOS decides when the check runs (typically a few times a day once the app is used regularly), so an alert may arrive hours after the FDA posts a recall rather than minutes. Accepted: hours is still weeks faster than the news cycle, and a push server would be the first backend the project has. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-09-19 — "About this medication" is limited to what the drug is for, sourced from MedlinePlus, with a link out.** Reeha asked whether the app should show drug facts even when nothing is recalled. Yes, but narrowly: two sentences from the National Library of Medicine's patient page (via RxNorm → MedlinePlus Connect, both NLM, both receiving only the drug name) and a "Read more" link. No dosing, interactions, or side effects — those sit against the "never suggest treatments" rule, and the commercial apps already do them with pharmaceutical funding. Rxcall's identity is the neutral watcher. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-11-06 — A tapped recall notification opens the medication, and the recall itself when the alert named just one.** The notification already carried the medication name in `userInfo`, but nothing read it, so tapping an alert landed on the plain list. `NotificationRouter` now receives the tap and the list screen navigates to it. When the check found exactly one new recall the notification also carries its recall number and the app opens that recall directly; with several, the medication screen listing them all is the better landing. The second push is deferred by one runloop turn, because pushing two levels inside a single SwiftUI update makes NavigationStack fault ("tried to update multiple times per frame") — it happens to arrive anyway, but that isn't a promise SwiftUI makes. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)

**2026-11-06 — Say plainly that Rxcall is not the FDA, and that its data is United States only.** Two things the app knew but never said. It credits the FDA and the National Library of Medicine as sources but never stated it is independent of them, which openFDA's terms ask of anyone using the data and which matters more when the subject is a government safety notice. And every recall comes from the FDA's enforcement reports, so for a medication bought outside the US the app finds nothing — and "no ongoing recalls" reads as reassurance rather than as "we have no idea." Both are now in the first-run notice and on the data-sources screen, which the notice change also made scrollable so the longer text survives the largest accessibility size. — Reeha Tabassum (author), Ruhi Tabassum (reviewer)
